# Plan: Make Atlas Layers a First-Class Citizen

**Status:** Awaiting approval (revised after adversarial council review) · **Author:** investigation synthesis (4 parallel agents) + Codex council · **Date:** 2026-06-21

> **Revision note (council review).** A deep adversarial review (Codex, 4 reviewers) plus
> direct source verification corrected three load-bearing M1 assumptions and de-risked one.
> Material changes folded in below: (a) **Schaefer labels carry no RGB** — native coloring
> must come from a shipped Yeo-network table, not `label.color`; (b) **U8 label volumes break
> integer IDs** under `R8Unorm` — label layers need an integer-preserving upload contract;
> (c) **LUT-alpha show/hide requires a shader RGBA+alpha change in M1**, not a free M4 add-on;
> (d) **the colormap LUT is a single shared resource** (one `RenderLoopService`) — the
> fan-out risk is dropped. The palette LUT is now built **backend-side** (centralizes
> max-label checks, Schaefer fallback, registered-id authority).

## Goal

An atlas/parcellation overlay (Schaefer, Glasser, ASEG, Olsen-MTL) should render in its
**own discrete colors**, identify the **region under the cursor by name**, optionally show
**ROI boundaries**, and expose a **searchable region legend** — all integrated into the
existing unified Inspector/layer model rather than bolted on.

## Locked decisions (from review Q&A)

1. **Coloring:** prefer each atlas's **native colors**, and for atlases without them use the
   purpose-built **`neuroatlas::colors`** ROI-palette engine (NOT a hand-rolled table).
   Resolution order, verified against neuroatlas source:
   - **Glasser / ASEG / Olsen-MTL** — labels carry `color` (`.with_color(...)`) → per-region
     native colors directly.
   - **Schaefer** — labels carry `network`/`hemisphere` but **no `color`**, and `Network` has
     no RGB. → use `neuroatlas::colors` with **`NetworkHarmony`** (`default_palette_for_records`
     picks it for Schaefer): colors are anchored by Yeo network *and* made distinct within a
     network, with a slice-aware conflict graph so adjacent parcels stay separable. This
     gives the recognizable network look **and** per-parcel distinctness at once — dissolving
     the earlier "network table vs. 400 distinct colors" tension.
   - **Other / no-color atlases** — `neuroatlas::colors` with `MaximinView` (maximally
     distinct, slice-aware).
   - The `PaletteKind` (NetworkHarmony / MaximinView / RuleHcl / Embedding) is exposed as the
     palette-mode control (M5); the frontend `AtlasPaletteKind` already mirrors it 1:1.
2. **Legend:** a **grouped "Regions" section inside the Inspector** — current-region card →
   network-grouped accordion + search → outline-mode selector. Virtualized; per-network and
   per-parcel show/hide and select. (No separate panel/drawer.)
3. **Boundaries:** add an **all-parcellation-boundary** mode **and keep** the existing
   single-selected-label outline.
4. **Process:** this written plan is approved before any code is written.

## Principle that drives the legend density solution

Never render 400 flat rows. Three data-driven levers (the neuroatlas `Label` carries
`network` + `hemisphere`, so no name-parsing):
- **Hierarchy** — 400 parcels collapse to ~17 networks × 2 hemispheres (~17 collapsed rows).
- **Context over enumeration** — the pinned **current-region card** (parcel under the
  crosshair) answers "what am I looking at" with zero scrolling.
- **Search/jump** — typing finds any parcel directly; browsing all 400 is rare and lives in
  expand-on-demand virtualized sub-lists.

## Current state: a finished frontend waiting on an unbuilt backend

Atlas display was front-loaded into the React app (commit `52915039`); the Rust half was
largely never built. Four broken seams:

**A. Coloring.** A 400-label volume renders as continuous **Jet** because:
- `get_atlas_palette` / `register_categorical_colormap` have **no Rust handler** (only stale
  autogenerated permission stubs), so `AtlasPaletteService.applyToVolumeLayer` throws into a
  swallowed `try/catch` → layer falls back to a continuous default.
- The `render_view` payload (`ui2/src/services/apiService.ts:95-108`) forwards only the
  colormap **string**, never `colormapId`.
- **Linchpin:** even in `layerMode == label`, both active masked shaders color via
  `textureSample(colormapLutTexture, samplerLinear, vec2(intensity_norm, 0.5), id)`
  (`core/render_loop/shaders/slice_world_space_masked.wgsl:446-447`, and the optimized
  variant `:443-444`). Label mode fixes *sampling* (nearest + round,
  `…masked.wgsl:356-362`) but not *coloring*.
- GPU side is ready: `COLORMAP_LUT_WIDTH = 2048` with `CUSTOM_COLORMAP_SLOTS = 64`
  (`core/render_loop/src/texture_manager.rs:17,20`) and a working uploader
  `RenderLoopService::upsert_custom_colormap` (`core/render_loop/src/lib.rs:745`) — **dead,
  no caller**.

**B. Labels discarded (volume path).** `load_atlas_unified`
(`core/atlases/src/service.rs:631`) builds the real neuroatlas `Atlas`, reads only
`atlas.n_regions()` (~`:671`), and drops it. The **surface** path already extracts a full
table → `SurfaceAtlasLabelInfo {id,name,color,hemisphere,network}`
(`core/atlases/src/types.rs:294`, populated `service.rs:1039-1053`). The volume path has no
equivalent, so `AtlasMetadata` (`types.rs:244`) carries only `n_regions`.

**C. Hover is wired and inert.** The provider pipeline, an unused `'atlas'` status-bar slot
(`StatusBar.tsx:90`), and a tooltip `'atlas-region'` case (`TooltipOverlay.tsx:65-72`) all
exist. `ui2/src/services/hoverProviders/atlasProvider.ts:31-41` is a literal
`return null` stub. The value sampler **already exists**: `sample_layer_value_at_world`
(`core/api_bridge/src/lib.rs:6909`, nearest-neighbor).

**D. Outline half-works.** Single-selected-label outline is real and active
(`SliceFeatureUbo` at bind group 3, `core/render_loop/src/ubo.rs:224-250`; shader
`…masked.wgsl:255-285`; command `update_slice_outline` `lib.rs:5637`). But it early-returns
when `selected_label_id == 0` (the default), so toggling Outline does nothing until a label
is chosen, and there is **no all-boundaries mode**. The declarative path
(`LayerOutlineState` on the render payload, `render_bridge_adapter.rs:194-222`) gates on
`enabled && selected_label_id > 0 && layer_mode == Label`.

## Target data flow

```
neuroatlas Atlas.labels()  →  AtlasLabelInfo[] {id,name,color?,network,hemisphere}
        │  (NEW: volume path extracts the table, like the surface path already does)
        ▼
load_atlas → AtlasMetadata.labels  →  bridge AtlasLoadResult  →  Layer.atlasLabels (TS)
        │                                                             │
        │                                                             ├─► Inspector Regions section (legend)
        │                                                             └─► atlasProvider hover (value→name, local)
        ▼
get_atlas_palette(atlas_id, kind?, seed?)   ← BACKEND wraps neuroatlas::colors
        │   • native label.color when present, else records_for_atlas → roi_palette(kind)
        │   • returns RoiPaletteLut{lut_rgb=(max_label+1)*3, kind, seed, max_label} + legend[]
        ▼
register_categorical_colormap(max_label, lut_rgb)   ← BACKEND packs + uploads
        │   • builds COLORMAP_LUT_WIDTH*4 RGBA row, texel k = color of label k, alpha=visible
        │   • validates max_label ≤ 2047; upsert_custom_colormap(key,&row) → colormapId
        ▼
render_view payload forwards {layerMode:'label', colormapId}  →  LayerState.colormap_id
        │   (backend validates colormapId is a registered/known id — no arbitrary u32)
        ▼
masked shader: if layer_mode==LABEL → c = textureLoad(LUT, vec2(label_id,0), id, 0) (RGBA, exact)
                                       final_alpha = layer_alpha * c.a ; id 0 ⇒ alpha 0
```

LUT convention: a `COLORMAP_LUT_WIDTH` (=2048) wide RGBA row where **texel k = color of
label k** for `k ≤ max_label` (Schaefer max 1000 < 2048); **alpha channel encodes per-label
visibility** (M4 show/hide); texels beyond `max_label` transparent. Shader indexes by
`textureLoad(colormapLutTexture, vec2<i32>(label_id,0), i32(colormap_id), 0)` — exact, no
sampler interpolation, no `intensity_norm`. **The LUT is built backend-side**, not in the
frontend, so max-label limits, the Schaefer Yeo fallback, the alpha row format, and
registered-id authority live in one place. `upsert_custom_colormap(key: String,
rgba_lut_row: &[u8])` already enforces the exact `2048*4` byte length and returns a stable id
keyed by `key` (idempotent re-upload — ideal for show/hide).

## Milestones

Each milestone is independently shippable and ends with a concrete verification.

### M1 — Discrete native coloring (the headline fix)

**Objective:** Schaefer renders in its canonical (Yeo-network) colors and Glasser/ASEG/Olsen
in their per-region colors — not a continuous Jet gradient.

**M1 preflight (do first — these are correctness gates, not nice-to-haves):**
- **Confirm the atlas volume upload format.** `choose_optimal_format` maps U8/I8 →
  `R8Unorm`, which normalizes samples to 0..1 and **collapses integer label IDs** under
  `round()`. Verify what dtype/format the loaded atlas volume actually gets
  (`core/render_loop/src/{smart,multi}_texture_manager.rs`). Bundled Schaefer/Glasser are
  int16/32 → `R16Float` (exact integers ≤ 2048) and survive, but the **label-layer upload
  contract must force an integer-preserving format** (`R32Float`, or `R16Float` only when
  `max_label ≤ 2048`) and **never `R8Unorm`** — otherwise user-loaded U8 label maps break.
- **Confirm `textureLoad` on the colormap binding.** The LUT is a sampled
  `texture_2d_array<f32>`; `textureLoad` (integer fetch) is allowed alongside the existing
  `textureSample` of builtin colormaps — no nearest-sampler addition needed. Sanity-check at
  compile time.

Backend (`core/atlases`, `core/api_bridge`, `core/bridge_types`):
- Extend `load_atlas_unified` to also extract the label table from the loaded `Atlas`
  (`labels()` → `AtlasLabelInfo{id,name,color:Option,network,hemisphere}`). Generalize the
  `load_concrete_atlas!` macro to return `(n_regions, Vec<AtlasLabelInfo>)`. Reuse the
  surface `SurfaceAtlasLabelInfo` shape (rename to a shared `AtlasLabelInfo`).
- Add `labels: Vec<AtlasLabelInfo>` to `AtlasMetadata` (`#[ts(export)]`); flows to the UI via
  `AtlasLoadResult.atlas_metadata`.
- **Revive the two backend commands the frontend already calls** (both currently have no
  Rust handler — this is the swallowed-error gap), as thin wrappers over `neuroatlas::colors`:
  - **`get_atlas_palette(atlas_id, kind?, seed?)`** → if the atlas labels carry native
    `color`, build `lut_rgb` from those; otherwise `records_for_atlas(&atlas)` →
    `default_palette_for_records` (or explicit `kind`) → `roi_palette` →
    `roi_palette_lut` + `palette_legend`. Returns `RoiPaletteLut{lut_rgb,kind,seed,max_label}`
    + `legend[]`. **Caching split:** `records_for_atlas` is heavy (per-ROI centroid + conflict
    graph) — compute it **once at `load_atlas`** (already in `spawn_blocking`, with progress)
    and cache the records keyed by atlas config; `get_atlas_palette(kind)` then re-runs only
    the cheap `roi_palette` recipe, so switching `PaletteKind` (M5) doesn't reload the atlas.
  - **`register_categorical_colormap(max_label, lut_rgb)`** → pack the `(max_label+1)*3` RGB
    into a `COLORMAP_LUT_WIDTH*4` RGBA row with **texel k = color of label k** (direct, NOT
    stretched to fill 2048), alpha=visible, id 0 + tail transparent; reject `max_label > 2047`;
    `upsert_custom_colormap(key, &row)` → stable `colormapId`.
  - Full 4-step command registration for both (`build.rs` COMMANDS, `generate_handler!`,
    `transport.ts`, `permissions/default.toml`). Remove the stale autogenerated permission
    stub for `get_atlas_palette` and replace with the real entry.
  - The label/legend table the UI persists (M2 hover, M4 legend) is the `palette_legend`
    output (`{label_id, roi, color, network, hemisphere}`) — single source.
- Note: the prior design indexed the LUT via the continuous `intensity_norm` path with an
  `intensity: [-0.5, max_label+0.5]` window hack (still visible in `AtlasPaletteService`).
  We **drop that** for label layers — `textureLoad(label_id)` is exact and needs no window.

Shader (`core/render_loop/shaders/slice_world_space_masked.wgsl` + `…optimized_masked.wgsl`):
- In the color stage, branch on `layer_mode == LAYER_MODE_LABEL`: `label_id =
  i32(round(raw_value))`; **fetch full RGBA** via
  `let c = textureLoad(colormapLutTexture, vec2<i32>(label_id, 0), i32(colormap_id), 0);`
  use `c.rgb` for color and **fold `c.a` into the final fragment alpha**
  (`final_alpha = layer_alpha * threshold_gate * c.a`), with label id 0 ⇒ alpha 0. This is
  what makes M4 per-label show/hide work (LUT alpha = visibility). Keep scalar/mask paths
  unchanged. Clamp `label_id` to `[0, LUT_WIDTH)`; warn if an atlas exceeds 2047.

Payload + adapter (carry the id declaratively — do **not** reuse the index-based imperative
`update_layer_colormap`, since `render_view` rebuilds `LayerConfig` from JSON each frame):
- `apiService.ts` per-layer payload: add `colormapId`. `LayerState` (`lib.rs:7917`) gains
  `colormap_id: Option<u32>`; `render_bridge_adapter` prefers it for label layers and
  **validates it is a backend-registered id** (reject/ignore unknown ids — no confused-deputy
  GPU state).

Frontend:
- `AtlasPaletteService` already orchestrates `get_atlas_palette` → `register_categorical_colormap`
  → sets `atlasPaletteKind/Seed/MaxLabel` + `colormapId`; with the backend handlers now real,
  this path lights up. The only frontend change: **persist the returned `legend[]` onto the
  layer** (currently dropped after registration) for M2 hover + M4 legend, and drop the
  `intensity:[-0.5,max+0.5]` window assignment for label layers.

**Definition of done:** Schaefer 400/17 renders `NetworkHarmony`-colored (network-anchored,
parcels distinct); Glasser/ASEG render their native per-region colors; switching `PaletteKind`
re-colors; the Inspector continuous colormap no longer governs label color; opacity/visibility
still work. **Verify:** app screenshot per atlas; Rust unit tests for (a) palette resolution
(native vs. `neuroatlas::colors` engine selection incl. Schaefer→NetworkHarmony), (b) LUT-row
packing (texel k == color of label k, alpha), (c) `max_label > 2047` rejection; a render
regression test (extend `tests/slice_outline_render_test.rs`) asserting exact label color +
that id 0 is transparent; a command-contract test that an unregistered `colormap_id` is
rejected.

### M2 — Region identity (hover + crosshair), frontend-only

**Objective:** hovering/click shows the parcel name.

- **Command-surface fix first (verified gap):** `sample_layer_value_at_world` is in
  `generate_handler!` (`lib.rs:11083`) and `transport.ts:56` but is **missing from
  `build.rs` COMMANDS and `permissions/default.toml`** (only `sample_world_coordinate` /
  `allow-sample-world-coordinate` are present). Add the command + `allow-…` permission so the
  UI can actually invoke it. So M2 is *not* purely frontend.
- Replace the `atlasProvider.ts` stub: for the active atlas layer, call
  `sample_layer_value_at_world(layerId, worldMm)` (returns the raw CPU nearest-neighbor value,
  not a normalized GPU sample), round to an integer label id, look up
  name/network/hemisphere in the layer's `atlasLabels`. No *new* backend command beyond the
  registration fix.
- The display sinks already exist (`StatusBar` `'atlas'` slot, `TooltipOverlay`
  `'atlas-region'`, `HoverContext.activeAtlasId`). Wire the current-region into the Regions
  card (M4) from the same lookup.

**Definition of done:** hover a parcel → tooltip + status bar show e.g.
`Atlas: LH VisCent ExStr 1 (Visual)`; background → no region. **Verify:** app screenshot +
vitest for value→name mapping including id 0 and out-of-range.

### M3 — Boundaries: all-parcellation + single-select

**Objective:** show every ROI border at once, keep selected-region outlining, fix the no-op.

- `SliceFeatureUbo` (`ubo.rs:224`) + WGSL mirror: add `outline_mode` (0=off, 1=single,
  2=all). Generalize `sampleSelectedLabelOutline` so mode 2 draws `outline_color` wherever a
  4-neighbor label differs from a non-zero center (no `selected_label_id` match required);
  mode 1 keeps current behavior.
- **Hidden-label semantics (decide explicitly):** with M4 visibility encoded in LUT alpha, a
  hidden parcel should **not** contribute borders. The neighbor-differs test treats a label
  whose LUT alpha is 0 as background, so boundaries are drawn only between visible regions.
  (The outline path samples label ids independently of color today; this rule must be added
  so `all` mode stays consistent with show/hide.)
- Extend `LayerOutlineState` + declarative adapter + `update_slice_outline` with `mode`.
- `RenderSection`/Regions: replace the single Outline toggle with an `off / all / one`
  selector (per mockup). For `one` with `selectedLabelId == 0`, default to the
  current-crosshair region so it's never a silent no-op.

**Definition of done:** `all` overlays full parcellation borders; `one` outlines the picked
region; thickness/color controls affect both. **Verify:** app screenshots for `all` and
`one`; extend the outline render test with an all-boundaries case.

### M4 — Grouped Inspector "Regions" section

**Objective:** the chosen legend/browser, integrated in the Inspector.

- New `RegionsSection.tsx`, rendered when `layerMode==='label'` && `atlasLabels` present.
  Layout (approved mockup): pinned **current-region card** → **search** (filter all labels)
  → **network-grouped accordion** (group by `network`; collapsed; chip + name + count +
  show/hide eye + select-group) → expand → **virtualized parcel sub-list** (swatch, name,
  show/hide; click → select + single-outline + jump crosshair to region centroid) →
  **outline-mode selector** + region count.
- Two-way sync: crosshair pick → highlight + auto-scroll the matching region; legend click →
  drive selection/outline/jump.
- **Show/hide via LUT alpha** (cheap; relies on the M1 shader change that folds `lut.a` into
  final alpha — *not* free without it): hiding a label sets its texel alpha to 0 and
  re-uploads the row via `register_categorical_colormap` (idempotent on the same `key`);
  network hide = all its labels. Hidden labels also drop out of `all`-boundary drawing (M3).
- Virtualization: add a lightweight dep (`@tanstack/react-virtual`) or hand-roll windowing
  (decide at implementation; prefer the dep for correctness).

**Definition of done:** legend lists networks, expands to parcels, search filters, current
region highlights/auto-scrolls, click selects+outlines+jumps, per-parcel/network show-hide
works. **Verify:** app walkthrough + vitest for grouping, search filter, and visibility-alpha
LUT recompute.

### M5 — Label-layer control hygiene + dead-code cleanup

**Objective:** the Inspector stops offering continuous-volume controls for label layers; remove dangling code.

- For `layerMode==='label'`: hide/repurpose continuous **Intensity window**, **Threshold**,
  and the continuous **Colormap** picker; replace colormap with a **palette-mode** control
  driven by `ATLAS_PALETTE_OPTIONS` (`network_harmony` · `maximin_view` · `rule_hcl` ·
  `embedding`) plus an **Atlas-native** entry when the atlas defines colors. Changing it
  re-requests `get_atlas_palette(kind)` and re-registers. Keep Visible/Opacity/Blend.
- Remove dead code: the unused imperative `ApiService.updateSliceOutline` path (keep the
  declarative one); stale `'AtlasPanel'` panel-type refs (`layoutService.ts:97,169,375`;
  `GoldenLayoutRoot.tsx:302,339,536,574`); unused `CustomColormapArena`
  (`core/colormap/src/lib.rs:50`). (Note: `get_atlas_palette` is now implemented, not removed.)

**Definition of done:** label layers show only label-appropriate controls; `cargo clippy`
and `pnpm lint` clean; no references to removed symbols.

## Open risks (post-council)

**Resolved / de-risked by review:**
- **Shared colormap LUT** — there is a *single* `RenderLoopService` under `BridgeState`
  shared by `render_view`/`render_views` and comparison/mosaic orchestration. No fan-out
  needed; **fan-out machinery is descoped** unless a second backend renderer is introduced.
- **`textureLoad` viability** — allowed on the existing sampled `texture_2d_array<f32>` LUT;
  no nearest-sampler fallback required.

**Live risks, owned in M1 preflight:**
1. **Label-volume integer fidelity** — `R8Unorm` (U8/I8) normalizes and collapses IDs. Force
   an integer-preserving format for label layers (`R32Float`, or `R16Float` for
   `max_label ≤ 2048`); add a U8 regression/reject path. Bundled atlases (int16/32 →
   `R16Float`) are exact, but the contract must be explicit so user label maps don't silently
   corrupt.
2. **Schaefer has no native RGB** — color source is the shipped Yeo table (by-network), not
   `label.color`. The "native colors" headline is true only with that table in place; the
   qualitative per-parcel mode is the distinct-color alternative.
3. **`max_label > 2047`** — reject at registration with a clear error (texel = label scheme
   caps at LUT width 2048). Not hit by bundled atlases.
4. **Trust boundary** — `render_view` must accept only backend-registered `colormap_id`s, not
   arbitrary u32 from the frontend.
5. **64 custom-colormap slots** — enough for typical sessions; the uploader is keyed by
   `String` (idempotent re-upload), so re-registering the same atlas reuses its slot. Add
   eviction only if many distinct atlases are loaded at once.
