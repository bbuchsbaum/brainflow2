A BIDS browser for Brainflow: three directions

Round 1 of the design review. Each direction is drawn inside the real Brainflow shell (top bar, Files panel with its BIDS view mode, Inspector, bottom dock, status bar) using the live --bf-* tokens and IBM Plex. All three read from the same backend that exists today: scan_bids_dataset, get_bids_events, and the validator.

The goal is to let a researcher understand a dataset in seconds: what exists, what is missing, what differs, what looks wrong, and then open any run in the viewer with one action.

A · Matrix B · Dossier C · Query

A · Matrix

  • The coverage matrix is the dataset. Every cell is one run.
  • Margins carry demographics and motion, aligned to rows.
  • Cells encode presence, acquisition variant, issue and QC outlier.

B · Dossier

  • A generated, readable report: one sentence summary, then sections.
  • Small multiples for participants, acquisitions, QC and task designs.
  • Sidenotes give sources and definitions.

C · Query

  • Entity query bar (sub, ses, task, run, variant, qc) over a dense run list.
  • Grouped by acquisition variant. Keyboard first.
  • Large preview: mosaic, carpet plot with FD, sidecar diff, events.
