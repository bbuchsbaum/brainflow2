# NeuroTabs population exploration: implementation evidence

Objective: implement [the complete population exploration plan](neurotabs-population-exploration.md), including its linked plotting extension. This ledger records evidence and outstanding work; it does not replace or narrow that plan.

## Current delivery

The first backend increment supplies reusable, equally weighted descriptive reductions in [`field_table::population`](../../core/field_table/src/population.rs). `FieldMoments` accepts finite measurements with optional validity masks and exposes local eligible/valid counts, mean, sample SD, mean absolute magnitude, cancellation and sign counts. Empty selections produce unavailable values. Spatial blocks and disjoint observation-block merges share the kernel. Numerical arrays remain outside frontend state.

Existing [file materialization](../../core/field_table/src/materialize.rs) now uses centered f64 moments and local denominators. Mean-only streaming uses compact mean/count storage; role reductions use blocks of 16,384 locations for numerical scratch. The existing role-loader still retains decoded input arrays, and z-score export still holds full-grid moments. These are not certified memory-bounded live-evaluation paths.

The SD reducer now exports sample SD with `ddof=1`. Existing descriptive z-scores retain `ddof=0`, use cohort moments computed before rounding the exported mean, and become unavailable at zero dispersion. This is not a group t-test. Output manifests state the observation unit and numerical/missingness conventions; manifest version 2 invalidates earlier cached calculations. Volume reductions check affine compatibility in addition to dimensions. Matching grids do not prove anatomical alignment.

Explicit participant summaries are now available from the Population lens's **Analysis unit** control. Users declare an exact participant-ID metadata column or explicitly declare each observation a distinct person; names and filenames do not infer identity. The default remains an observation summary. Participant mode either requires one selected row per person or explicitly averages that person's selected rows before giving each person equal weight. Complete, uniquely keyed metadata is required. Supported table, discovery and CSV/TSV manifest imports retain a record per observation independently of the compact preview; legacy datasets with only an incomplete preview remain ineligible for metadata-dependent grouping.

Native fields reduce within each participant at each voxel with f64 intermediate means, then compute between-participant moments and local valid counts. Probe summaries first reduce the spatial response within each observation, then reduce those responses within participants; with differing spatial missingness this is not necessarily the value obtained by spatially averaging the participant mean map. Original observations remain in the plot, gallery and focus view. Participant configuration changes reuse the sampled context and preserve membership, reference and probe. The configuration is session state, not yet a saved analysis recipe or a model adapter.

## Requirements ledger

The frontend increment extends the existing Studio store with explicit working membership, fixed/complement reference semantics, pinned/hover probes, relationship-fit identity and bounded working-selection undo/redo. Eligibility is derived separately from list search, issue highlighting and sorting. Metadata filters now refuse incomplete or ambiguous keyed rows, and the strip reports the context issue. Search preserves the focused person even when hidden from the list; valid eligibility changes reconcile focus, including clearing it for an empty context. Bootstrap resets these definitions atomically and advances an import generation. The population-probe panel now wires working-selection controls and frontend plot-query identity. Reference controls and durable live-summary provenance remain unfinished.

Population sampling now uses a CPU cache with a 512 MiB default decoded-payload budget and LRU eviction. Cache misses create a private single-file NIfTI snapshot, compute its SHA-256 and decode those same bytes on one admitted blocking worker. Warm hits revalidate filesystem stamps, including inode/change time on Unix. This freshness shortcut does not detect changes invisible to those stamps. Source files are capped at 2 GiB for snapshotting; header dimensions enforce conservative decode admission. Decoder scratch/process overhead are not certified by the resident payload budget. Panel stop/query replacement now requests cooperative native cancellation; dataset-scoped cache teardown remains unfinished.

Multi-frame sources require explicit frame selection instead of silently using frame zero; one frame is sampled without allocating a full temporal series at every voxel. Frozen-source digests can be supplied for mismatch rejection. The sample-frame metadata retains per-observation source revision, frame index, finite count and failure reason. This is not yet whole-query input freezing, a temporal-axis contract or complete participant/support/units provenance. Spatial means, medians, interpolated quantiles and dispersion moments avoid float32 intermediate overflow.

The Studio center now includes [`PopulationProbePanel`](../../ui2/src/components/studio/PopulationProbePanel.tsx): an all-observation point plot, pinned crosshair or hover probe, radius control, selected descriptive mean, missing count and per-source status. Clicking focuses an original observation; Shift-click or the observation table changes working membership. All/none/focused-only and undo reuse the sampled frame. Hiding the plot preserves its probe and selection. The shared plot encoder retains row identity through missing-value filtering and supplies keyboard focus/selection equivalents.

[`PopulationProbeController`](../../ui2/src/services/studio/PopulationProbeController.ts) owns one issued sampling call plus the latest pending definition, coalesces requests, and rejects obsolete completions. Its query records workspace/import/set/feature identity, resolved context sources and spatial probe. Focus, reference and working membership do not cause resampling. Previous results remain labeled during a new query within the same dataset; changing dataset identity clears them. Ambiguous/unavailable bindings and unresolved frame selectors are refused. [`PopulationProbeActions`](../../ui2/src/services/studio/PopulationProbeActions.ts) owns store mutations and hover-subscription disposal. This lifecycle now cancels issued scalar/trace calls through SampleProvider and the native sampling ticket registry. Immutable saved-query source retention and native cross-workspace hover provenance remain unfinished.

Native sampling now accepts optional expiring UUID tickets and exposes `cancel_population_sample`. The bounded registry retains cancellation-before-start tombstones and rejects ticket replay. Cancellation interrupts cache admission waits and is checked between members, during snapshot copy, and before/after decode and sample closures. Issued decoder calls and template-service source resolution are cooperative boundaries, not forcibly preemptible jobs; their permits remain owned until they exit. The frontend rejects an aborted promise immediately and the backend refuses to publish its partial result. Clients without a ticket retain the existing call shape.

A whole-query source guard captures all resolved file identities before member sampling and rechecks before returning. Changes, deletions and missing-to-available transitions invalidate the complete result. This is optimistic filesystem consistency using the existing stamps, not immutable retention of every source or protection against changes invisible to metadata. Per-source digests continue to identify decoded bytes.

The live-slice increment adds [`PopulationSliceEngine`](../../core/api_bridge/src/population_slice.rs) and the `evaluate_population_slice` / `release_population_slice` commands. It gathers unique native voxels needed by one visible plane, retains a bounded observation matrix, and reuses that matrix for working-selection, summary and focus changes. It computes mean, sample SD, cancellation and coverage with the shared kernel; the focused image contains actual observed samples. A missing file, incompatible grid, unresolved 4D frame or frozen-digest mismatch fails the whole field query. Source guards run before and after evaluation. Rotated orthogonal grids are accepted; sheared grids currently require explicit resampling. Display sampling is nearest-neighbor and float32; this is not original-f64 export equivalence.

[`PopulationLens`](../../ui2/src/components/studio/PopulationLens.tsx) shows the live summary and focused original using the shared viewport and image-surface primitives. Audited volume imports now open this lens. The Studio coordinator bypasses ordinary file/GPU loading and file materialization for population focus changes. Both panes share geometry, crosshair and a fixed value scale for mean/individual comparison. Nonnegative summaries have a separate adjustable scale. Clicking pins a probe; hover feeds the existing plot preview; navigation preserves the pinned location. Holding the preview button temporarily removes the focused observation from the field query and releasing restores it without changing canonical membership. The participant controls now also support removal of every selected row belonging to the focused person, while the focused image remains an original observation.

[`PopulationSliceService`](../../ui2/src/services/studio/PopulationSliceService.ts) owns one active native query plus its latest replacement, cancellation tickets, decoded response arrays and reference-counted bitmap leases. Dataset changes clear displayed results and request native plane-cache release; mounted view leases protect retired images until React releases them. The native plane cache has a 128 MiB sample/geometry payload budget and one admission slot. Decoded source-cache residency, result arrays, numerical scratch, JSON IPC and bitmap memory remain separate allocations; dataset-scoped decoded-source teardown is still outstanding. Component close releases its plane cache, and previous results retain their own query/geometry labels while pending.
